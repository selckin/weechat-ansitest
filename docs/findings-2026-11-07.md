## WeeChat findings on the branch

### 1. SI from terminfo resets all attributes on IRC (irc path)

`/exec` does not set `TERM`, so commands inherit WeeChat's. With
`TERM=tmux-256color`, `screen` or `linux`, terminfo's `sgr` ends with SI
(`\017`, shift in, which selects the G0 character set), and so does `sgr0`.
WeeChat passes SI through, and on IRC `\x0f` is the reset code: every
attribute that `sgr` sets is lost.

```
/exec -o printf '\033[0;1m\017bold?\033[m\017\n'     # screen/tmux sgr(bold): not bold on IRC
TERM=screen /exec -o tput bold ...                    # same, with terminfo itself
```

Expected: SI changes no attribute (in a terminal it only selects the
character set). Actual: on IRC, the text after SI is not bold.
632 cases: `ti/{linux,tmux-256color,screen}/sgr/*` with attributes.
Involved: `irc_color_decode_ansi`, which copies text (and C0 controls) as
is. A possible fix is to remove the C0 controls that are IRC formatting
codes (`\x02 \x03 \x04 \x0f \x11 \x16 \x1d \x1e \x1f`), or at least SI and
SO, from the text. The gui paths are not affected.

### 2. Unterminated or cancelled sequences are shown as text (all paths)

`GUI_COLOR_REGEX_ANSI_DECODE` (src/gui/gui-color.h) only removes complete
sequences. When a sequence is cut off, the regex removes only `ESC` plus
the next byte, and the parameters stay as text. A terminal shows none of
these characters.

```
/exec printf 'a1\033]0;title\n'          # shows "a10;title", expected "a1"
/exec printf 'a1\033[1;2\n'              # shows "a11;2", expected "a1"
/exec printf '\033[123\0339\n'           # shows "123": ESC cancels the CSI
/exec printf '\033]Something\0339\n'     # shows "Something": ESC cancels the OSC
/exec printf '\033[12\030AB\n'           # shows "12AB", expected "AB" (CAN cancels)
/exec printf '\033[12\1773m\n'           # shows "123m", expected "" (DEL is ignored in a CSI)
/exec printf '\033PHello\007\n'          # shows "Hello": DCS/APC/PM/SOS ended by BEL
```

Cases: `hw/osc-unterminated`, `hw/csi-unterminated`, and 12 `lvx/` cases
from libvterm's parser tests (`Escape cancels ...`, `CAN cancels ...`,
`DCS BEL`, `APC BEL`, `PM BEL`, `SOS BEL`, `DEL ignored within CSI`).
Involved: `GUI_COLOR_REGEX_ANSI_DECODE`, which both
`gui_color_decode_ansi` and `irc_color_decode_ansi` use.

Note on BEL: xterm ends only OSC with BEL. DCS, APC, PM and SOS end with
ST, so libvterm is more lenient than xterm there. In both terminals,
however, the text inside the string is not shown.

### 3. SGR 6 (rapid blink) is ignored (gui paths)

```
/exec printf '\033[6mblink\033[0m\n'
```

Expected: blink, like SGR 5. Actual: no attribute. Case: `hw/rapid-blink`.
Involved: `gui_color_decode_ansi_cb`, which has no `case 6`. On the irc path
blink is dropped anyway.

### 4. A stray ESC stays in the stored line (gui and gui-ansi paths)

A lone ESC that starts no escape sequence stays in the decoded line, where
`\x1B` is also WeeChat's internal "remove attribute" code.

```
/exec printf 'a1\033\033[1ma2\n'     # ESC ESC [1m
/exec printf 'a1\033\n'               # ESC at the end of the line
```

- Stored line (gui path): `a1\x1b\x1a\x01a2` and `a1\x1b\x1c`. The bare
  `\x1b` is followed by another code. The curses display copes: it
  consumes the byte after `\x1b` only when it is a valid attribute, so
  `a2` is shown in bold. But the line holds a byte that the ANSI decoder
  should have removed.
- Logger (gui-ansi path): `gui_color_encode_ansi` always consumes the byte
  after `\x1b`, so the bold code is lost and the logger writes `a1^Aa2`.
  The same goes for anything else that uses the encoder, like the relay
  with ANSI colors.

Cases: `hw/esc-esc` (gui, gui-ansi), `hw/lone-esc-end` (gui). Involved:
`gui_color_decode_ansi`, which could remove a lone ESC, and
`gui_color_encode_ansi` (cases `GUI_COLOR_SET_ATTR_CHAR` and
`GUI_COLOR_REMOVE_ATTR_CHAR`).

## Known divergences (accepted, listed in ansitest/divergences.py)

- SGR 21 removes bold in WeeChat; ECMA-48 and xterm use it for double
  underline (`hw/sgr21`).
- On the irc path SGR 2 removes bold, so bold set after dim stays
  (`hw/dim-then-bold`).
- DECSTR (`CSI ! p`) is removed without resetting the attributes (libvterm
  pen test).
- libvterm brightens colors 0-7 with bold; WeeChat keeps the color
  (libvterm pen test).

## Not covered by the harness

- `4a19bdc` (bar delimiter color): the bar delimiter color is not in a
  buffer line, so neither `/exec` nor the display paths reach it.
- `14b9c10`, `ebc0876` (speed): the harness checks results, not time.
- `c823a8e` (non-UTF-8 bytes) is covered by `hw/osc-title-latin1`; the
  rest of the branch is described in `docs/fixes.md`.
- The gui decoder models a terminal with 16 colors or more and
  `weechat.look.color_real_white on`. Terminals with 8 colors (light colors
  shown as bold), `color_basic_force_bold` and `color_real_white off` are
  covered by the `print` and display paths, which were added after these
  findings.
